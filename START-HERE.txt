ESP32 INTERVALOMETER — v1.12, TWO DISPLAY EDITIONS
Launch preparation — 8 November 2026

CHOOSE ONE EDITION

OLED/R7Intervalometer
  SSD1306 128x64 monochrome I2C OLED; the working default for the new screen.
  SH1106 128x64 is an explicit alternative in DisplayConfig.h.
  Four connections: VIN 3.3V, GND, SCL GPIO18, SDA GPIO23.
  Brightness and screen sleep/wake; fixed panel color, no RGB themes.
  Library: Adafruit GFX with BusIO. Wire comes with the ESP32 core.
  Open OLED/R7Intervalometer/R7Intervalometer.ino.
  Upload guide: OLED/R7Intervalometer/QUICKSTART-OLED.txt.

TFT/R7Intervalometer
  ST7735S SPI color TFT, 80x160 pixels, used as 160x80 landscape.
  Eight connections: VCC 3.3V, GND, SCL GPIO18, SDA GPIO23, RES GPIO19,
  DC GPIO22, CS GPIO21, BLK GPIO13 (logic-controlled backlight input).
  Four color themes, LCD color calibration and backlight sleep/wake.
  Libraries: Adafruit ST7735/ST7789, GFX and BusIO.
  Open TFT/R7Intervalometer/R7Intervalometer.ino.
  Upload guide: TFT/R7Intervalometer/QUICKSTART-TFT.txt.

Both require ESP32 Dev Module, core 3.3.12 exactly; other builds are rejected. These are separate complete sketches.
Do not combine their files in one Arduino folder. Their Serial startup banners
identify Firmware 1.12 OLED or Firmware 1.12 TFT. Arduino compiles App.cpp;
the short .ino placeholder is intentional.

The SCL/SDA labels are I2C on the OLED and SPI on the TFT. Choose by actual
controller, resolution and interface, not the number or names of pins alone.
Neither firmware auto-detects the display model. The new physical OLED has not
yet been positively identified; 128x64 SSD1306 remains an assumption.

FRACTIONAL EXPOSURE EDITOR
Choose Settings > Shot mode first, then Settings > Exposure.
- Bulb: 1/10, 1/8, 1/5, 1/4, 1/2 s, then 1-86400 seconds; no 0 s option.
- Camera: shutter-speed REMINDER, including 1/100, 1/60 and 1/30 s.
  The display tells you to set the speed on the camera. The remote jack cannot
  transfer that setting. Choose a speed available on your camera.
- Trigger pulse still controls remote contact hold, separately from the reminder.
  The reminder does not change Gap; allow enough time for exposure and saving.
- Previous custom Bulb times are retained exactly unless changed with the encoder.
  A separate camera-speed record preserves the reminder independently.

SHARED FUNCTIONS
- Hardware-timed Bulb holds from 0.100 s to 24 hours.
- Camera mode sends a remote press; set short shutter speeds on the camera.
- Manual shutter press-and-hold, adjustable encoder sensitivity, 2s sequence lock.
- Pause/Stop, saved settings, Dry run, input and electrical timing diagnostics.
- Encoder GPIO32/33/27, shutter GPIO25 and focus GPIO26 remain the same.
- Camera state is applied before screen changes on manual press/release and Stop.

Exposure/capture/menu settings use the same saved records. Switching editions on
the same ESP32 with flash settings retained preserves them, including Dry run OFF.
TFT Theme/Panel and OLED brightness have separate records. Check Dry run after an
upload. No exposure starts automatically at boot.

DISPLAY-SPECIFIC LIMITS
OLED checks I2C transaction results and stops/releases on a reported failure;
Serial o retries initialization while idle. An ACK is not controller identification.
TFT has no panel acknowledgement on this wiring and cannot detect disconnection.
The 2.5 mm camera plug alone does not establish camera compatibility; the remote
pinout and electrical interface must match the optocoupler circuit in the README.

MAINTENANCE / VALIDATION
The eight platform/timer/input/capture/exposure/sequence core files are identical in both editions.
Run python3 tools/verify_editions.py to check them. Make future core fixes in both
copies; verification fails on drift. Application/rendering code remains specific
to each display and needs its own regression checks.
Run python3 tools/verify_editions.py --test to also run both host suites (requires
Python 3 and a C++ compiler supporting the sanitizers used by the tests).
Build each .ino separately in Arduino IDE for ESP32 Dev Module.

The launch validation report records compilation and host-test results. These
are software checks; neither edition was flashed or physically verified here.
Before publishing a hardware-tested release, confirm the actual OLED model and
check each fitted display, encoder, screen sleep/wake, Manual Shutter, lock/Stop
and a short live sequence. EXIF variation has not been proven resolved; timer
diagnostics measure GPIO command timestamps, not the camera's sensor exposure.

TRIGGER RELEASE FIX RETAINED FROM v1.10
Both editions now configure the release IRQ for flash-cache-safe operation and
remove flash-resident calls from its callback. TimerPlatform.h isolates the
SDK-specific adapter. See RELEASE-1.10.txt in either sketch for the mechanism,
software validation, upgrade checks and remaining physical-timing limitations.

To audit a compiled ELF with the bundled tool:
  python3 tools/verify_timer_iram.py /path/to/xtensa-esp32-elf-objdump firmware.elf
This checks the pinned normal ISR/final-assertion call chains, not physical timing.

INPUT AND STARTUP RECOVERY IN v1.11
Input checks between transfers are retained; v1.12 yields to the main loop for actions.
Home shows the raw switch level; Serial prints reset reason and button state.
OLED errors trigger bounded recovery with camera outputs OFF; interrupted shots
never restart automatically. STARTUP-CHECK.txt covers the power-supply comparison.
The physical intermittent startup problem has not been diagnosed or bench-tested.

TIMER / DISPLAY FREEZE REVIEW IN v1.12
- Timer driver calls run outside the application lock; shutter stays LOW until
  arming succeeds within its budget. Retries are bounded. Failure blocks capture.
- With a running loop, a missing callback releases the outputs, stops the
  sequence and records Release timeout instead of waiting indefinitely.
- Display callbacks only check for pending work. Button/timer events yield the
  frame; flash saves and menu/camera actions execute in the main loop. Rotation
  stays queued, so continuous turning does not starve every frame.
- TFT framebuffer allocation failure no longer loops forever. Capture is blocked
  and Serial diagnostics remain available.
See RELEASE-1.12.txt in either sketch. No wiring changes; replace all sketch files.
These fixes do not establish the physical freeze's cause or exact camera timing.
